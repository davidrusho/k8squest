# 💡 HINT 1: Observation and Analysis

Start by understanding the quota situation:

## Step 1: Check the Deployment and its Pods

```bash
kubectl get deployment,rs,pods -n k8squest
```

The Deployment exists, but READY is 0/1 and there are **no Pods at all**.
A quota rejects the Pod *creation request*, so the Pod never exists to be Pending.

## Step 2: Examine the ReplicaSet Events

```bash
kubectl describe rs -n k8squest
```

Look at the **Events** section. You should see:
```
Warning  FailedCreate  ... Error creating: pods "resource-hungry-app-..." is forbidden: exceeded quota: compute-quota, requested: requests.cpu=2500m ...
```

(`kubectl get events -n k8squest` shows the same line.) This tells you the ReplicaSet
cannot create the Pod because it requests more resources than the quota allows!

## Step 3: Check the ResourceQuota

```bash
kubectl describe resourcequota compute-quota -n k8squest
```

You'll see something like:
```
Resource         Used  Hard
--------         ----  ----
limits.cpu       0     4
limits.memory    0     4Gi
pods             0     10
requests.cpu     0     2        ← Only 2 CPUs available!
requests.memory  0     2Gi
```

## Step 4: Check Pod's Resource Requests

```bash
kubectl get deployment resource-hungry-app -n k8squest -o yaml | grep -A 4 requests
```

You'll see:
```yaml
requests:
  cpu: "2500m"  # ← Requesting 2.5 CPUs!
  memory: "1Gi"
```

## Understanding the Problem

**The Math:**
- Namespace quota allows: **2 CPUs total**
- Pod is requesting: **2.5 CPUs** (2500 millicores)
- 2.5 > 2 → **Quota exceeded!**

**Why quotas exist:**
- Prevent resource hogging
- Fair share across teams
- Protect cluster stability
- Cost control

## What You Need to Fix

Option 1: **Reduce the Pod template's resource requests** to fit within quota
Option 2: **Increase quota** if justified (usually not your call)

For this challenge: **Reduce the Pod template's resource requests**
